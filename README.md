# Baned Adder — баннеры в видео + нарезка на части

Локальный веб-редактор для Mac и iPhone. Загружаете видео (с устройства или **по ссылке YouTube / TikTok**) и рекламный баннер, выбираете длину частей и сколько раз показать рекламу, а приложение:

- **скачивает видео по ссылке** YouTube или TikTok: сразу в редактор или в «Загрузки»;
- **делит видео на части** нужной длины, разрезая в паузах речи и на смене сцен, а не посреди слова;
- **повторяет конец прошлой части в начале новой** (по умолчанию 15 с), чтобы зритель, долиставший до части 2 в TikTok, сразу понимал, где остановился;
- **вставляет рекламу**: видео замирает (стоп-кадр с размытием), появляется баннер, потом видео продолжается с того же места;
- добавляет надписи «Часть 2/5», «↺ Повтор из части 1», «Продолжение в части 3 →»;
- делает вертикальное видео 9:16 с размытым фоном, готовое для TikTok / Reels / Shorts.

Всё работает **локально**: видео не уходит в интернет — только в браузер или на ваш компьютер в домашней сети. Ключей, аккаунтов и облачных сервисов нет.

## Быстрый старт на Mac

1. Один раз установите [Homebrew](https://brew.sh), затем в Терминале:
   ```bash
   brew install node ffmpeg yt-dlp
   ```
   `yt-dlp` нужен только для скачивания по ссылкам YouTube и TikTok, без него всё остальное работает.
2. Скачайте проект (`Code → Download ZIP` или `git clone`) и запустите:
   ```bash
   cd baned-adder
   npm start
   ```
   Можно и без Терминала: двойной клик по `start.command` в Finder (при первом запуске: правый клик → «Открыть»).
3. Откройте **http://localhost:8787** в Safari или Chrome.

`npm install` не нужен: у проекта нет зависимостей, только встроенные модули Node.js.

## На iPhone

**Вариант 1 — через Mac (быстро, рекомендуется).** Запустите сервер на Mac, iPhone подключите к той же Wi-Fi сети. На Mac нажмите **«Открыть на iPhone»** и наведите камеру iPhone на QR-код (или введите адрес из Терминала, вида `http://192.168.1.23:8787`). Видео с iPhone обрабатывается на Mac через ffmpeg, а готовые части сохраняются кнопкой **«Сохранить / Поделиться» → «Сохранить видео»** прямо в «Фото».

**Вариант 2 — без Mac.** Приложение работает и полностью в браузере iPhone: анализ, превью и запись идут на самом телефоне. Для этого страницу нужно открыть по HTTPS, например через GitHub Pages:
`Settings → Pages → Source: GitHub Actions`, затем `Actions → Deploy to GitHub Pages → Run workflow`. На сайт выкладываются только файлы приложения, ваши видео никуда не загружаются. В Safari: «Поделиться» → «На экран Домой», и приложение откроется как обычное, в том числе без интернета.

> Запись в браузере идёт в реальном времени (часть 3 мин ≈ 3 мин записи). Не блокируйте экран и не сворачивайте Safari, пока идёт запись.

## Как пользоваться

1. **Видео.** Выберите файл (MP4, MOV, WebM, в том числе видео с iPhone) или вставьте ссылку YouTube / TikTok (см. ниже).
2. **Баннеры.** Картинка (PNG, JPG, WebP) или короткое видео. Можно добавить несколько: они будут показываться по очереди, случайно или всегда первый.
3. **Нарезка.** Длина одной части (кнопки 1:00…10:00 или своя), длина повтора, «умная нарезка», допуск сдвига разреза, режим «строго не длиннее».
4. **Реклама.**
   - *Пауза + баннер*: видео замирает, баннер выезжает, под ним идёт полоска-таймер, звук плавно затихает перед паузой и возвращается после.
   - *Поверх видео*: баннер поверх идущего видео, звук не прерывается.
   - Где ставить: «умно» (в паузах речи), равномерно или вручную по времени (`0:45, 2:10`).
   - Сколько раз в каждой части, отступы от начала и конца, длительность показа картинки, лимит длины видеобаннера.
   - Внешний вид: размер, положение, анимация, размытие и затемнение стоп-кадра, метка «Реклама», звук видеобаннера.
5. **Оформление.** Формат (9:16, 1:1, 4:5, 16:9 или как у исходника), заполнение кадра (размытый фон, обрезка, чёрные поля), разрешение, акцентный цвет, тексты надписей с переменными `{n}`, `{total}`, `{prev}`, `{next}`.
6. **План.** Схема показывает все части на шкале исходника: заштрихованная зона — повтор, ромбы — реклама, штрихи — найденные паузы и смены сцен. Нажмите на ромб, чтобы сразу посмотреть рекламную вставку.
7. **Превью.** Часть проигрывается со всей рекламой и надписями так же, как будет выглядеть файл.
8. **Готовые видео.** «Создать все части» или «Создать» у отдельной части. Затем «Скачать», «Скачать все по очереди» или «Сохранить / Поделиться».
9. **Подписи.** Шаблон текста для публикации (`{title} — часть {n}/{total} #fyp`), отдельная кнопка «Копировать» для каждой части.

Настройки сохраняются в браузере автоматически, а наборы можно сохранять как **пресеты** («Мой TikTok», «Reels 90 сек» и т. п.).

## Скачивание по ссылке (YouTube, TikTok)

В разделе «Видео» есть поле **«Ссылка на видео YouTube или TikTok»**. Подходят обычные ссылки, Shorts, `youtu.be`, `vm.tiktok.com`, а также текст, скопированный кнопкой «Поделиться» в TikTok: ссылка из него вытащится сама.

- **«Скачать и редактировать»** скачивает видео и сразу открывает его в редакторе. Файл уже лежит на компьютере, поэтому повторно ничего не загружается, анализ и рендер начинаются сразу. По умолчанию копия оригинала ещё и сохраняется в «Загрузки», это отключается галочкой под кнопками.
- **«Только скачать в Загрузки»** просто сохраняет видео. Потом его можно открыть в редакторе кнопкой «Открыть в редакторе», без повторного скачивания.
- На iPhone есть кнопка «Поделиться / в Фото», чтобы сохранить ролик в галерею.

Как это устроено: ссылку обрабатывает [yt-dlp](https://github.com/yt-dlp/yt-dlp) на вашем Mac. Видео берётся в MP4 (H.264 + AAC) до 1080p. Если сайт отдаёт только VP9/AV1/HEVC, файл автоматически перекодируется в H.264, чтобы он открывался в Safari, на iPhone и в браузерном движке. Скачивание работает, только когда сайт открыт с Mac, где запущен `npm start`, в том числе с iPhone по Wi-Fi: в одном браузере без сервера сайты YouTube и TikTok скачивать не дают. Принимаются только ссылки YouTube и TikTok.

> Скачивайте только видео, на которые у вас есть права: свои ролики или с разрешения автора. Перезалив чужого контента нарушает авторские права и правила площадок.

YouTube регулярно меняет защиту. Если скачивание вдруг перестало работать, обновите yt-dlp: `brew upgrade yt-dlp`. Для YouTube новым версиям yt-dlp нужен JavaScript-движок; приложение само передаёт yt-dlp ваш Node.js, ничего дополнительно ставить не нужно.

## Два движка обработки

| | Компьютер (ffmpeg) | Браузер |
|---|---|---|
| Где работает | Mac с запущенным `npm start`; с iPhone через Wi-Fi | любой современный браузер, в том числе iPhone без Mac |
| Скорость | быстрее реального времени (на Apple Silicon с VideoToolbox — в разы) | в реальном времени |
| Качество | H.264 MP4, x264 или аппаратный VideoToolbox | MP4 в Safari и новом Chrome, иначе WebM |
| Анализ пауз и сцен | ffmpeg (быстро) | Web Audio + покадровое сравнение |

Режим «Автоматически» выбирает ffmpeg, если сервер запущен и ffmpeg найден, иначе браузер. Графика (надписи, карточки баннеров) рисуется одним и тем же кодом в обоих движках, поэтому результат выглядит одинаково.

## Как работает «умная» нарезка

1. **Анализ.** Звук сводится в громкость с шагом 50 мс. Порог тишины адаптивный: он лежит между уровнем фонового шума и типичной громкостью, поэтому паузы находятся и в тихих записях, и в видео с фоновой музыкой. Смены сцен ищутся по разнице кадров (в ffmpeg фильтром `scene`, в браузере сравнением уменьшенных кадров с уточнением момента бинарным поиском).
2. **Число частей** считается так, чтобы каждая часть вместе с повтором и рекламой уложилась в заданную длину, а длины частей были примерно равны.
3. **Каждый разрез** ищется рядом с «идеальной» точкой (± допуск). Лучше всего оценивается смена сцены внутри паузы, затем длинная пауза, затем смена сцены. Если разрез сдвинулся, остаток видео снова делится поровну, чтобы последняя часть не раздувалась.
4. **Повтор** в начале следующей части тоже подстраивается под начало фразы.
5. **Реклама** ставится равномерно внутри части (не в повторе и не у краёв) и подтягивается к ближайшей паузе, чтобы видео «замирало» между фразами.
6. В строгом режиме длина части гарантирована: если пауз мало для очень коротких частей, разрезы делаются по ровному времени (об этом появится предупреждение).

## Структура проекта

```
public/                 веб-приложение (работает и без сервера)
  index.html, css/      интерфейс
  js/app.js             логика интерфейса
  js/core/              чистые модули, общие для браузера, сервера и тестов
    plan.js             планировщик: части, повторы, моменты рекламы, надписи
    layout.js           геометрия кадра, баннера и анимаций
    audio.js            поиск пауз в звуке
    settings.js         настройки по умолчанию и их проверка
  js/engine-browser.js  превью и запись в браузере (canvas + Web Audio + MediaRecorder)
  js/analyze-browser.js анализ в браузере
  js/engine-server.js   клиент локального сервера
  js/graphics.js        отрисовка надписей и карточек баннеров
  js/qr.js              QR-код для открытия на iPhone
  sw.js, manifest       офлайн-режим и установка на экран «Домой»
server/
  server.js             локальный HTTP-сервер без зависимостей
  downloader.js         скачивание по ссылкам YouTube/TikTok (yt-dlp)
  ffmpeg-graph.js       сборка filter_complex для ffmpeg
  media.js              ffprobe, анализ, запуск рендера
tests/                  тесты (node --test)
start.command           запуск двойным кликом на Mac
```

## Параметры запуска сервера

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8787` | порт |
| `HOST` | `0.0.0.0` | `127.0.0.1` закроет доступ из сети (iPhone не подключится) |
| `WORKSPACE` | системная временная папка `/baned-adder` | куда класть загрузки и готовые файлы |
| `KEEP_HOURS` | `24` | через сколько часов удалять временные файлы |
| `MAX_UPLOAD_GB` | `20` | максимальный размер загружаемого файла |
| `FFMPEG_PATH`, `FFPROBE_PATH` | `ffmpeg`, `ffprobe` | свои пути к ffmpeg |
| `YTDLP_PATH` | `yt-dlp` | свой путь к yt-dlp |

Пример: `PORT=9000 KEEP_HOURS=4 npm start`.

## Безопасность и приватность

- В репозитории нет и не нужно никаких ключей, токенов и `.env`. В `.gitignore` уже исключены `.env`, ключи, видеофайлы и рабочие папки.
- Сервер слушает домашнюю сеть, чтобы к нему мог подключиться iPhone. Им может воспользоваться любое устройство в этой же Wi-Fi сети, поэтому в публичных сетях (кафе, коворкинг) запускайте его с `HOST=127.0.0.1`.
- Файлы получают случайные имена, пути проверяются, ffmpeg запускается без оболочки (`spawn` с массивом аргументов), цвета и числа в настройках проверяются.
- Временные файлы удаляются автоматически через `KEEP_HOURS` часов.

## Частые вопросы

**Кнопки скачивания по ссылке неактивны.** Сайт должен быть открыт с Mac, где запущен `npm start`, и там должен стоять yt-dlp: `brew install yt-dlp`. После установки достаточно обновить страницу.

**«Сайт не отдал видео (ошибка 403)» или «подтвердите, что вы не робот».** Обновите yt-dlp: `brew upgrade yt-dlp`. Приватные, удалённые и видео с ограничением по возрасту скачать нельзя.

**«ffmpeg не найден».** Выполните `brew install ffmpeg` и перезапустите `npm start`. Без ffmpeg приложение всё равно работает, но рендер идёт в браузере.

**iPhone не открывает адрес.** Проверьте, что iPhone и Mac в одной Wi-Fi сети, а в «Системные настройки → Сеть → Файрвол» Node.js разрешены входящие подключения. Используйте адрес из Терминала, а не `localhost`.

**В браузере получился WebM.** Значит, браузер не умеет записывать MP4. Safari и Chrome 126+ умеют. Или запустите сервер с ffmpeg.

**Звук пропадает в превью на iPhone.** Сначала нажмите на любую кнопку воспроизведения: iOS разрешает звук только после касания. Проверьте также переключатель беззвучного режима.

**Какую длину выбрать для TikTok?** Обычно это 1–3 минуты на часть. Включите «Строго не длиннее», и ни одна часть не превысит заданную длину вместе с рекламой и повтором.
